Spawn Sinks: Standalone First, Pooled Bridge Optional

Expanded from the shipped Documentation~/ApiReference.md. Read the first section carefully: it states plainly what is in the box and what is not.

The plain statement

WaveDirector Pro works fully standalone, out of the box. Its built-in spawner needs nothing else installed, and that standalone path is the default truth of the product.

Pooling is an optional bridge: if you also own and install SpawnPool Pro — a separate product, not included with WaveDirector Pro — the director uses its pooling automatically. Nothing about the standalone path is a reduced version waiting for that bridge; it is a complete spawning path in its own right.

The one interface

The engine spawns only through ISpawnSink:

public interface ISpawnSink
{
    bool TrySpawn(in WaveSpawnRequest request, out WaveSpawnHandle handle);
    bool IsAlive(WaveSpawnHandle handle);
    void DespawnAll();
}

Alive contract: an enemy counts as cleared when its instance is destroyed or deactivated. Pooled despawns deactivate; kills deactivate or destroy — both already satisfy the contract, so no death callback is needed. (A destroyed instance reads as not-alive once destruction takes effect — immediately for DestroyImmediate, at frame end for Destroy.)

Returning false from TrySpawn (for example, a pool at its cap) makes the engine wait an interval and retry; the spawn is never dropped.

The three shipped paths

  1. InstantiateSpawnSink — the standalone fallback. Plain Instantiate; despawn by destroy. This is what runs when nothing else is installed and nothing is registered.
  2. PooledSpawnBridge — the optional bridge. Used automatically when SpawnPool Pro is installed. It binds that product's public PoolManager by type name at runtime; there is no compile-time reference in either direction, so each package installs and removes cleanly without the other, and neither package's installation, compilation, or removal can break the other. The cost is one reflection call per spawn, at wave cadence (a few calls per second, never per frame). The bridge also forwards each archetype's PrewarmCount to the pool on start.
  3. Your own sink, registered. Call WaveSinkRegistry.Register(sink) once and every Auto director uses it: your own pooling, your network wrapper, anything that implements the interface. Unregistering restores the default selection.

Choosing per director

WaveDirectorBehaviour.SinkMode chooses per director:

  • Auto — a registered custom sink wins; otherwise the pooled bridge when the separate pooling product is installed; otherwise the standalone fallback.
  • Pooled — the bridge path.
  • Instantiate — the standalone fallback, forced.

The home window's Spawning line always states, in plain language, which of the three paths is active in your project.
