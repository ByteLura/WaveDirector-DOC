Determinism and Seeds

Expanded from the shipped Documentation~/ApiReference.md.

The promise, stated exactly

Same wave set + same seed + same wave index = the same spawn queue — same archetypes, same order — on every machine and every run. That is the whole promise, and it is why a balance complaint can be reproduced exactly: send the set and the seed, and the cast that frustrated a player is the cast you get.

How it is kept

  • The engine uses its own seeded random generator; it never calls Unity's global random. Engine time is injected by the driver through Tick(deltaTime); nothing inside the engine reads a global clock.
  • Per-wave stream isolation: each wave's composition draws from a stream derived from (seed, wave index). Editing, adding, or reordering later waves never changes an earlier wave's composition. (Reordering the waves themselves changes which definition sits at an index — that is authoring, and it is supposed to.)
  • Spawn-point choice uses the same seeded discipline, so identical runs pick identical points.
  • Previews cannot disagree with runs: PreviewComposition(index, seed) — and the timeline's Simulate All — compose through the same code path the engine runs.

Seed posture

A new wave set carries an explicit seed on the set, and that is the default. Per-run randomization is an opt-in toggle on the director (RandomizeSeedOnStart), off by default: determinism is the reproducibility promise, variety is a choice you switch on knowingly.

Working with seeds

  • Found a wave that felt wrong? Note the seed from the set, reproduce the exact cast, then fix the number that caused it — a cost, a weight, a budget.
  • Want a fresh run for a stream or a test build? Change the set's seed in the timeline toolbar and every wave re-casts, still reproducibly.
  • In Loop and Endless modes, difficulty follows the absolute wave index, so a repeated definition at index 9 casts with index 9's budget and index 9's stream — the preview and the engine agree on this exactly.
